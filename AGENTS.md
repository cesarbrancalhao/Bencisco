## Project

Bencisco FTO — method tutorial + alg database. Astro 7 + Starlight, Tailwind CSS v4 (`@tailwindcss/vite`), static output, no backend.

- `src/content/docs/` — MDX pages (Starlight content root). Sidebar is configured manually in `astro.config.mjs`. Advanced pages get a sidebar badge via frontmatter; advanced subsections use `<details>`.
- `src/data/*.yaml` — alg databases, zod-validated via the `algs` collection in `src/content.config.ts`. Each case: `alg` (CIF community notation, with brackets/slices resolved — drives the applet; equals the showcase alg when the showcase has no rotation), `scramble` (inverse of `alg`, precomputed for inspection/correction; used by the renderer as the twisty-player setup-alg instead of computing the inverse at runtime), `showcase_alg` (community notation — the written alg shown to the user, bold), `showcase_label` (optional colored prefix for the showcase alg, e.g. `"EIF"` / `"CIF -> EIF"`), `eif_alg` (Edge-in-Front notation, non-bold with `(EIF)` colored prefix; `eif_label` overrides the label text), `name` (prominent label), `family` (small secondary label). cubing.js names FTO faces differently, so the community→Twizzle face map (π: F→BL, B→R, L→B, R→L, BL→BR, BR→F) is applied to `alg` at render time by `cifToTwizzle()` in `src/scripts/fto-notation.ts` — never stored in the data. `setup_prefix`/`preset`/suffix fields are cubing-frame and pass through untranslated. Optional per-file `setup_prefix` (e.g. `"LBLv"` on last-layer files) is prepended to each case's setup-alg so yellow is on top; a case-level `preset` field overrides it for individual cases. Optional per-file `top_down: true` (1ll3t, olp, tcp) renders thumbnails from a raised top-down camera angle instead of the default flat face-on view. In `1ll3t.yaml`, showcase algs use CIF community notation (`S`/`H` = sledge/hedge, `{X,Y}` = reorient with X on top and Y in front, `[U]` = pre-AUF, `Rs`/`Fs` = slice suffixes); the `alg` field holds the same alg resolved to plain CIF moves (no brackets, `S`/`H`/slices expanded, wide moves as `Xw`). `tcp.yaml` was converted with the same pipeline and validated 1:1 against the 1ll3t T-family states (see `tx/tcp-conversion.md`); extra alg variants are shown via `showcase_alg1`, `showcase_alg2`, ... `olp.yaml` was converted from plain CIF (no brackets; `H`/`S`/`S'` expanded, `(Uv)` rotations kept in `alg` but stripped from `scramble` — see `tx/olp-conversion.md`); each case pairs an Even and an Odd solution via `showcase_alg`/`showcase_alg1` with `showcase_label`s. The collection glob is `**/*.yaml`, so subdirectories work: `src/data/samples/` holds example-solve data (one case per solve step, `id` referenced from the MDX). Samples set file-level `map_scramble: true` because their `scramble` is stored in CIF community notation and must be π-mapped at render time exactly like `alg` — unset means the 1ll3t/tcp/olp convention (scramble handed to cubing.js unmapped, `alg_prefix` compensates the frame).
- `src/components/SolveStep.astro` — renders one example-solve step (`src` + case `id` props) as a direct-embed `PuzzleViewer`; applies `cifToTwizzle()` to the scramble when the data file sets `map_scramble: true` (PuzzleViewer itself always expects a cubing-frame scramble).
- `src/components/PuzzleViewer.astro` — thumbnail-first FTO viewer; `cubing/twisty` is dynamically imported on click (never in the initial bundle). Use direct embed (no `thumbnail` prop) only on low-density pages. `hintFacelets` prop (also on `AlgTable`/`CaseCard`) keeps twisty's hint facelets on instead of forcing `hint-facelets="none"` (used on the TCP page). `stickeringMask` prop passes a cubing.js stickering mask (`experimental-stickering-mask-orbits`) through to the player; normally set file-level via `stickering_mask` in the YAML (used by `olp.yaml`, which hides everything but the OLP recognition stickers) and honored by the thumbnail renderer.
- `src/components/CaseDensityToggle.astro` — dice-button cases-per-row toggle (2/3/4) rendered by `AlgTable` at the top of every case grid. Persists per-page to `localStorage` (`fto-case-density-<src>`, keyed by the YAML data file name) and sets `data-density` on its own `.alg-density-root`; `global.css` overrides the grid columns (lg breakpoint) and applies `zoom` to `.case-card` (1.15 for 2-up, 0.9 for 4-up) so only card contents (fonts, previews, interactive player) are magnified/shrunk.
- `public/thumbnails/<case-id>.webp` — per-case previews (unsolved case state), generated by `npm run imgs` (screenshots `/thumbnail-renderer/` via playwright-core + system Chrome; falls back to `placeholder.svg` when missing). Re-run after editing YAML data.

## Development

When starting the dev server, use background mode:

```
astro dev --background
```

Manage the background server with `astro dev stop`, `astro dev status`, and `astro dev logs`.

Verify changes with `npm run build` and `npx astro check`.
