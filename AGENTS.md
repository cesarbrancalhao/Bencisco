## Project

Bencisco FTO — method tutorial + alg database. Astro 7 + Starlight, Tailwind CSS v4 (`@tailwindcss/vite`), static output, no backend.

- `src/content/docs/` — MDX pages (Starlight content root). Sidebar is configured manually in `astro.config.mjs`. Advanced pages get a sidebar badge via frontmatter; advanced subsections use `<details>`.
- `src/data/*.yaml` — alg databases, zod-validated via the `algs` collection in `src/content.config.ts`. Each case: `alg` (Twizzle notation — drives the applet), `showcase_alg` (community notation — the written alg shown to the user, bold), `showcase_label` (optional colored prefix for the showcase alg, e.g. `"EIF"` / `"CIF -> EIF"`), `eif_alg` (Edge-in-Front notation, non-bold with `(EIF)` colored prefix; `eif_label` overrides the label text), `name` (prominent label), `family` (small secondary label). Optional per-file `setup_prefix` (e.g. `"Rv T"` on last-layer files) is prepended to each case's setup-alg so yellow is on top; a case-level `preset` field overrides it for individual cases. Optional per-file `top_down: true` (1ll3t, olp, tcp) renders thumbnails from a raised top-down camera angle instead of the default flat face-on view. In `1ll3t.yaml`, showcase algs use CIF community notation (`S`/`H` = sledge/hedge, `{X,Y}` = reorient with X on top and Y in front, `[U]` = pre-AUF, `Rs`/`Fs` = slice suffixes); the `alg` field holds the same alg resolved to plain Twizzle CIF moves (community→Twizzle face map: F→BL, B→R, L→B, R→L, BL→BR, BR→F).
- `src/components/PuzzleViewer.astro` — thumbnail-first FTO viewer; `cubing/twisty` is dynamically imported on click (never in the initial bundle). Use direct embed (no `thumbnail` prop) only on low-density pages.
- `public/thumbnails/<case-id>.webp` — per-case previews (unsolved case state), generated by `npm run imgs` (screenshots `/thumbnail-renderer/` via playwright-core + system Chrome; falls back to `placeholder.svg` when missing). Re-run after editing YAML data.

## Development

When starting the dev server, use background mode:

```
astro dev --background
```

Manage the background server with `astro dev stop`, `astro dev status`, and `astro dev logs`.

Verify changes with `npm run build` and `npx astro check`.
